# Nine core fixes before beta — 2026-09-11

The pre-beta review found nine behavioral defects despite the existing wiring
tests passing. All nine have been corrected locally and covered by regression
checks. This is a development checkpoint, not a beta release.

## Changes

- **30 — Be more efficient:** Count the Field Zone within the three-card S/T
  limit. Gate additional Field Spell activation and setting while allowing
  replacement and activation of an already-set Field Spell. Direct placement
  overflow is reconciled by letting the controller choose excess cards to send
  to the GY by rule, with a guard against recursive adjustment.
- **31 — Droll limit:** Use the card's owner for the return-to-hand restriction,
  so a stolen monster is checked against its owner's quota.
- **35 — First turn advantage:** Supply the first-turn draw when the room does
  not already enable it; respect skipped Draw Phases and avoid duplicate draws.
- **38 — This card is trash:** Negate the effect rather than its activation;
  remove the incorrect boolean-versus-zero fallback handling.
- **39 — Mirror:** Exclude only Tokens generated by this core from mirroring,
  allowing other Token summons to produce a mirror without recursive spawning.
- **46 — Once Punch:** Attach the first attack's ATK bonus at the Damage Step,
  so a canceled attack cannot leave a persistent buff. Keep defensive resets.
- **53 — Boss:** Preserve the monster's own effects while applying immunity to
  other card effects.
- **55 — Gambling:** Always request the mandatory rolled draw, including when
  the Deck is too small, allowing the engine to enforce deck-out.
- **56 — Energy:** Determine each action's cost independently of other legality
  probes, preventing a checked action from overwriting another action's price.

## Validation

- Main Lua suite: **30 tests passed**; combat and limit regression suites passed.
- Tooling suite: **10 tests passed**.
- Engine suite: **4 tests passed**, including loading all **38 cores**, core 35
  with native first-turn-draw flags and skipped draws, and core 55 deck-out.
- In a temporary copy, substituting each of the nine baseline implementations
  caused its new regression checks to fail. This confirms the checks distinguish
  the repaired behavior from the original defects.

Engine validation also exposed a defect in the duel driver: setting
`OCG_NewCardInfo.duelist` equal to `team` incorrectly left player 1's Deck empty.
The driver now uses duelist **0 for both teams**, identifying the first duelist
within each team. A broken fixture could otherwise misattribute failures to a
core, so this correction is part of the validation work.

## Remaining boundaries

No full LAN duel or installation verification has been performed for this
checkpoint. No external publication has occurred. Existing partial-enforcement
limitations remain, including core 31 allowing a single multi-card addition to
overshoot the remaining quota. Do not interpret loading all cores as complete
match coverage or a release certification.
